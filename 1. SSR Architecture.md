### Build a SSR application from scratch:

#### 1. CSR vs SSR

##### CSR

![avatar](/imgs/CSR.png)

the process is like below:

1. the browser send a request to the server;
2. the server response with **an empty html**;
3. the browser is in a white screen state;
4. the browser sent multiple request to the server for css, image and js
5. the server response with the corresponding resources;
6. the broswer excute the js;
7. the broswer is to render the page

the disadvantages:

1. the browser stays in a white screen for a while;
2. not good for SEO

##### SSR

![avatar](/imgs/SSR.png)
the process is like below:

1. the browser send a request to the server;
2. the server response with **a full content html**;
3. the broswer rendering the page;
4. the browser send multiple requests to the server for css, image and js
5. the server response with the corresponding resources;
6. the broswer excute the js;
7. **the browser take controll over the subsequent process**

#### 2. build express server

```js
const express = require("express");
const app = express();

app.get("*", (req, res) => {
  const html = `
  <!DOCTYPE html>
  <html lang='en'>
    <head>
      <meta charset='UTF-8'/>
    </head>
   <body>
      <div id='root'>
         hello
      </div>
   </body>
  </html>
`;
  res.send(html);
});
```
- react component could be parsed into string;
- using ReactDom.renderToString from `react-dom/server`

#### 3. server render React

react component on the server side.

import Home from "./pages/Home";

##### Problems:

1. node.js cannot recognize jsx syntax and cannot use import by default;
   A: use webpack to compile, transer the `JSXs` to `createElement()`. Packages involved: `babel-loader` and `preset-react`;

2. react-dom is used for browser, not for node.js
   A: instead of ReactDom.render(), we use ReactDom.renderToString().

3. on the server side, not like the front end that need a bundle.js included all packages, instead, the server side itsself could install all packages and after webpack building, the bundle.js no need to include all packages?  
   - webpack output will target on broswer by default: set target into node in webpack.config.js;
   - server side packages should not be included into bundle.js: using `externals` and `webpack-node-externals` to exclude node_modules
  
4. register a domEvent on the server side, while the code is passed to the client side, the event does not exist on the source code, why?
   - The framework has its own event system (it does not process inline events).
   - For security reasons, to prevent XSS.
   - To ensure consistency between SSR and client-side hydration.

#### Client Render React

1. Hydrate:
   ```js
   // ReactDom.render(<App />,document.getElementById('root'));
   ReactDom.hydrate(<App />,document.getElementById('root'));
   ```
   - server will use webpack to build a bundle.js again for front-end use
   - server will add a script tag with this bundle.js in the server rendering component
   the process is like below:
   ![avatar](/imgs/client-render.png)
   - browser to request html page;
   - server response with a html page with a `<script>`.
   - brwoser request js file 
   - browser is to take over the subsequent process and excute js

3. The html structure on both side should be same.
   as the server has parsed each React element, on the client side, it does not have to be rendered again, where only events(js) need to be added to. Instead of using render, using hydrate is more approperiate.(virtual dom is created, but real dom is not)

#### Introduce router

##### how to use router in server side

1. That introduce BrowserRouter into client side works fine. THe process is like this: As the server side can't implement BrowserRouter, so when it comes to route like `/news`, the sever side return the `/home` page, and the client side got the js file, and the browser runs the js file, and as a result of the route, client side go to the `/news` page. So, the news page is rendered, but the source html is home page.
   1. use staticRouter on the server side.
   ```js
   <StaticRouter location={location} context={context}></StaticRouter>
   ```
   2. in order to dynamicly get location and set the value into StaticRouter location property, http request need to be passed into `<App location={location} context={context}/>`
